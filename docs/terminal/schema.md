# Terminal Data Contracts

Status: proposed
Contract version: `terminal/1`
Date: 2026-08-04

## 1. Conventions

- IDs are UUID strings generated by the host.
- Timestamps are ISO 8601 UTC strings at IPC boundaries and integer Unix milliseconds in SQLite.
- Paths are canonical absolute host paths unless a field explicitly says `relative`.
- All renderer-to-host payloads are schema-validated.
- Event `sequence` is monotonic per terminal session.
- Optional fields are absent rather than set to invalid sentinel values.

```ts
type TerminalSessionId = string
type TerminalCommandId = string
type ProjectId = string
type IsoTimestamp = string
```

## 2. Core models

### 2.1 Shell profile

```ts
type ShellIntegrationKind = 'powershell' | 'bash' | 'none'
type TerminalPresentationMode = 'blocks' | 'classic'

interface TerminalShellProfile {
  id: string
  label: string
  executable: string
  args: string[]
  integration: ShellIntegrationKind
  defaultPresentation: TerminalPresentationMode
  source: 'detected' | 'user'
  available: boolean
  unavailableReason?: string
}
```

### 2.2 Persistence policy

```ts
interface TerminalPersistencePolicy {
  private: boolean
  saveCommands: boolean
  saveOutput: boolean
  maxOutputBytesPerCommand: number
  retentionDays: number | null
}
```

Invariants:

- `private === true` forces `saveCommands === false` and `saveOutput === false` in the host.
- `saveOutput === true` is invalid when `saveCommands === false`.
- `maxOutputBytesPerCommand` is host-clamped; proposed range is `0..5_242_880` bytes.

### 2.6 Output chunk

```ts
interface TerminalOutputChunk {
  sessionId: TerminalSessionId
  commandId?: TerminalCommandId
  sequence: number
  stream: 'pty'
  data: string
  byteLength: number
  replay: boolean
}
```

PTY output is ordered, not split into semantic stdout/stderr streams because a terminal PTY merges presentation output.

## 3. Shell integration events

Payloads are encoded in the private OSC frame described in the architecture.

```ts
type ShellIntegrationEvent =
  | ShellPromptStart
  | ShellPromptReady
  | ShellCommandStart
  | ShellOutputStart
  | ShellCommandEnd
  | ShellCwdChanged
  | ShellIntegrationError

interface ShellEventBase {
  protocol: 1
  shell: 'powershell' | 'bash'
  timestampMs: number
}

interface ShellPromptStart extends ShellEventBase {
  event: 'prompt_start'
}

interface ShellPromptReady extends ShellEventBase {
  event: 'prompt_ready'
  cwd: string
}

interface ShellCommandStart extends ShellEventBase {
  event: 'command_start'
  command: string
  cwd: string
}

interface ShellOutputStart extends ShellEventBase {
  event: 'output_start'
}

interface ShellCommandEnd extends ShellEventBase {
  event: 'command_end'
  exitCode: number
  cwd: string
}

interface ShellCwdChanged extends ShellEventBase {
  event: 'cwd'
  cwd: string
}

interface ShellIntegrationError extends ShellEventBase {
  event: 'integration_error'
  code: string
  message: string
}
```

Marker payload size is capped at 32 KiB after decoding. Oversized payloads are rejected and count toward degraded-mode detection.

## 4. IPC API

The final implementation should expose a narrow typed API from preload. Names below replace the current create/write/resize/kill-only surface additively during migration.

### 4.1 Requests

```ts
interface TerminalRendererApi {
  listProfiles(): Promise<TerminalShellProfile[]>
  listLive(projectId: ProjectId): Promise<TerminalSessionSnapshot[]>

  create(input: TerminalCreateInput): Promise<TerminalSessionSnapshot>
  write(input: TerminalWriteInput): Promise<void>
  resize(input: TerminalResizeInput): Promise<void>
  interrupt(input: TerminalSessionRef): Promise<void>
  terminate(input: TerminalSessionRef): Promise<void>
  setPresentation(input: TerminalSetPresentationInput): Promise<void>

  subscribe(input: TerminalSubscribeInput): Promise<TerminalSubscriptionSnapshot>
  acknowledge(input: TerminalAcknowledgeInput): Promise<void>

  searchHistory(input: TerminalHistoryQuery): Promise<TerminalHistoryPage>
  deleteHistory(input: TerminalHistoryDeleteInput): Promise<TerminalHistoryDeleteResult>
  updateHistory(input: TerminalHistoryUpdateInput): Promise<void>
}

interface TerminalCreateInput {
  projectId: ProjectId
  projectRoot: string
  cwd: string
  shellProfileId: string
  cols: number
  rows: number
  presentation?: TerminalPresentationMode
  privacy?: Partial<TerminalPersistencePolicy>
  launch?: {
    command: string
    args: string[]
  }
}

interface TerminalWriteInput {
  sessionId: TerminalSessionId
  data: string
}

interface TerminalResizeInput {
  sessionId: TerminalSessionId
  cols: number
  rows: number
}

interface TerminalSessionRef {
  sessionId: TerminalSessionId
}

interface TerminalSetPresentationInput extends TerminalSessionRef {
  mode: TerminalPresentationMode
}

interface TerminalSubscribeInput extends TerminalSessionRef {
  afterSequence?: number
}

interface TerminalAcknowledgeInput extends TerminalSessionRef {
  sequence: number
}
```

Host validation limits:

- `data`: maximum 1 MiB per write invocation;
- `cols`: `2..1000`;
- `rows`: `1..1000`;
- `cwd`: existing directory and allowed for the project/session policy;
- `launch.args`: bounded array and string lengths;
- renderer may reference only a live session returned to its window/project context.

## 6. SQLite schema

All tables live in a desktop-owned SQLite database at `~/.enpiistudio/terminal/history.db`. This is intentionally separate from the agent sidecar's current `~/.enpiistudio/sessions/index.db`. Migration version names are illustrative and should follow the terminal repository's migration mechanism.

```sql
CREATE TABLE terminal_schema_migrations (
  version INTEGER PRIMARY KEY,
  applied_at_ms INTEGER NOT NULL
);

CREATE TABLE terminal_sessions (
  id TEXT PRIMARY KEY,
  project_id TEXT NOT NULL,
  project_root TEXT NOT NULL,
  shell_profile_id TEXT NOT NULL,
  shell_label TEXT NOT NULL,
  initial_cwd TEXT NOT NULL,
  final_cwd TEXT,
  title TEXT NOT NULL,
  integration_status TEXT NOT NULL,
  presentation_mode TEXT NOT NULL,
  private INTEGER NOT NULL DEFAULT 0 CHECK (private IN (0, 1)),
  save_commands INTEGER NOT NULL DEFAULT 1 CHECK (save_commands IN (0, 1)),
  save_output INTEGER NOT NULL DEFAULT 0 CHECK (save_output IN (0, 1)),
  max_output_bytes INTEGER NOT NULL DEFAULT 0,
  started_at_ms INTEGER NOT NULL,
  ended_at_ms INTEGER,
  exit_code INTEGER,
  exit_signal INTEGER
);

CREATE INDEX terminal_sessions_project_started_idx
  ON terminal_sessions(project_id, started_at_ms DESC);

CREATE TABLE terminal_commands (
  id TEXT PRIMARY KEY,
  session_id TEXT NOT NULL REFERENCES terminal_sessions(id) ON DELETE CASCADE,
  project_id TEXT NOT NULL,
  sequence INTEGER NOT NULL,
  command_text TEXT,
  command_search TEXT,
  command_display TEXT NOT NULL,
  cwd TEXT NOT NULL,
  shell_profile_id TEXT NOT NULL,
  status TEXT NOT NULL,
  storage_disposition TEXT NOT NULL,
  started_at_ms INTEGER NOT NULL,
  completed_at_ms INTEGER,
  duration_ms INTEGER,
  exit_code INTEGER,
  output_bytes INTEGER NOT NULL DEFAULT 0,
  persisted_output_bytes INTEGER NOT NULL DEFAULT 0,
  output_truncated INTEGER NOT NULL DEFAULT 0 CHECK (output_truncated IN (0, 1)),
  contains_ansi INTEGER NOT NULL DEFAULT 0 CHECK (contains_ansi IN (0, 1)),
  pinned INTEGER NOT NULL DEFAULT 0 CHECK (pinned IN (0, 1)),
  git_repository_root TEXT,
  git_head TEXT,
  git_detached INTEGER CHECK (git_detached IN (0, 1)),
  git_dirty INTEGER CHECK (git_dirty IN (0, 1)),
  git_ahead INTEGER,
  git_behind INTEGER,
  git_observed_at_ms INTEGER,
  UNIQUE(session_id, sequence)
);

CREATE INDEX terminal_commands_project_started_idx
  ON terminal_commands(project_id, started_at_ms DESC, id DESC);

CREATE INDEX terminal_commands_session_sequence_idx
  ON terminal_commands(session_id, sequence);

CREATE INDEX terminal_commands_cwd_started_idx
  ON terminal_commands(project_id, cwd, started_at_ms DESC);

CREATE INDEX terminal_commands_status_started_idx
  ON terminal_commands(project_id, status, started_at_ms DESC);

CREATE INDEX terminal_commands_pinned_idx
  ON terminal_commands(project_id, pinned, started_at_ms DESC);

CREATE TABLE terminal_output_chunks (
  command_id TEXT NOT NULL REFERENCES terminal_commands(id) ON DELETE CASCADE,
  chunk_index INTEGER NOT NULL,
  data BLOB NOT NULL,
  byte_length INTEGER NOT NULL,
  created_at_ms INTEGER NOT NULL,
  PRIMARY KEY(command_id, chunk_index)
);
```

### Search strategy

Initial implementation:

- normalize `command_search` to a case-folded text value;
- use parameterized `LIKE` with project/time/status indexes narrowing candidates;
- cap result pages;
- add FTS only after measured need and with a migration compatible with bundled SQLite.

Do not create FTS or a second search service preemptively.

## 7. Persistence rules

### Commands

| Situation | Stored command |
|---|---|
| Normal session, allowed command | Raw command + normalized search text |
| Output disabled | Command metadata only |
| Private session | No command row |
| Hidden/no-echo input | EnStudio does not create a command/history record from the forwarded keystrokes |
| Redaction match | Redacted/omitted according to rule action |
| DB unavailable | In-memory block only |

### Output

- Count bytes using UTF-8 encoded size at the host boundary.
- Stop adding durable chunks at the per-command limit.
- Continue live rendering after persistence truncation.
- Chunk persisted data, proposed maximum 64 KiB each.
- Compression MAY be added only after measuring database size and CPU trade-offs.
- Binary-looking output MAY be excluded from durable storage while still rendering live through xterm.

### Retention

A maintenance task runs at most once per application day and:

1. selects non-pinned commands older than the configured retention;
2. deletes in bounded batches;
3. leaves private sessions absent by design;
4. does not block startup or terminal I/O;
5. performs database compaction only through an explicit maintenance action or safe idle policy.

## 8. Redaction contract

```ts
type TerminalRedactionAction = 'redact' | 'exclude'

interface TerminalRedactionRule {
  id: string
  enabled: boolean
  source: 'built_in' | 'user'
  target: 'command' | 'output' | 'both'
  pattern: string
  flags?: string
  action: TerminalRedactionAction
}
```

Rules are compiled in the host with timeout/complexity protections appropriate to the chosen regex implementation. Invalid user rules are disabled with a visible settings error.

Built-in rules are conservative. They should prefer excluding obvious inline credentials over attempting partial masking that may miss transformed secrets. Redaction does not replace private mode.

## 9. Migration and compatibility

- Existing `terminal:create`, `write`, `resize`, `kill`, `data`, and `exit` IPC remain during the feature-flag period.
- The new API is added alongside it and used only by the new terminal controller.
- No existing terminal history needs migration because the current surface does not own durable structured command history.
- Terminal tables use additive migrations and foreign keys with cascading output cleanup.
- If the feature flag is disabled, new rows remain readable for future re-enable but are not required by classic mode.

## 10. Contract tests

- Serialize/validate every request and event variant.
- Reject invalid enum values, dimensions, paths, output limits, and oversized writes.
- Verify session ownership cannot be bypassed with another session id.
- Verify private mode creates no durable rows.
- Verify command deletion cascades to output chunks.
- Verify cursor pagination is stable for equal timestamps.
- Verify parser event sequence maps deterministically to block status.
